# 11 到访内容维护

维护者编辑根目录的 `public-places.json`，确认内容后随网站发布。不需要账号或后台；普通用户的个人地点仍只保存在其浏览器。

首个正式地点为维护者确认到访的上海世博文化公园，腾讯 POI 名称、编号、地址和坐标已于 2026-09-06 在线核对。停车、童车通行、母婴室与园内餐饮依据公开资料填写，来源及核实日期保存在该地点的 `sources` 中；童车通行依据为允许婴儿专用车入园，不代表所有景点路线均无障碍。亲子卫生间尚无明确依据，到访日期待维护者补充。儿童友好「很友好」与父母便利「较便利」依据维护者反馈：草坪大、有帐篷区、适合遛娃，停车位多，但餐饮选择有限、有时需要排队。好玩程度「很好玩」由维护者确认，当前三项综合为 4.3 / 5 星。统一头像为维护者提供照片制作的 `assets/11-avatar.jpg`；不把旧预制点或测试数据填成 11 的经历。

## 引导问卷

先按 README 启动本地服务，再打开 [评分维护页](http://127.0.0.1:4173/maintainer.html)，选择已有公开地点，依次填写「是否好玩」「儿童友好」「便利程度」。每项会带入已有等级和理由，可以保留、修改或选择「还不确定，暂不评价」。未确定的维度不会被当成低分。

预览后点击「保存到本地草稿」或「保存并维护其他地点」。已保存内容在同一浏览器、同一本地地址刷新或关闭后可恢复；待发布列表可重新打开编辑。全部维护完成后，下载 `public-places.draft.json` 或复制完整 JSON，批量导出是包含已保存修改的完整公开数据快照，不是增量补丁；未保存修改不包含在内。未编辑地点、POI 身份、来源、年龄等字段保留。

草稿使用独立存储键 `playmap_maintainer_draft_v1`。保存失败、版本不兼容或其他页面更新时，不覆盖旧草稿；未保存内容可从本次预览数据复制留存。公开数据变化时显示版本提醒，由维护者或其授权的工作助手核对合并。清除浏览器数据会删除草稿，请导出备份。

把草稿交给维护者或其授权的工作助手（如 Codex、WorkBuddy）核对差异，再按明确指令更新 `public-places.json`、测试和发布。维护页不会写入个人 localStorage，也不会直接修改仓库或线上数据；它是静态草稿工具，没有账号或管理员权限。新增地点在本地地图搜索腾讯 POI，打开添加面板，点击「11 去过，填写评分」即可携带名称、地址、类别和坐标直达第一题。与已有公开 POI 重合时更新原记录，不重复新增。这个入口仅在 localhost、127.0.0.1 或 [::1] 显示；维护页在其他域名禁用，并由 `_config.yml` 排除在 GitHub Pages 发布之外。

不同浏览器、不同端口以及 `localhost` 与 `127.0.0.1` 不共享草稿。换工具接手时，在原浏览器下载 JSON 后交给接手者；维护页目前没有文件导入功能。待发布列表按保存时的公开版本比较；当公开数据与已保存快照完全一致时，刷新后不再显示待发布修改。

## 三步发布（WorkBuddy 接管）

内容准备：确认真实到访与确切腾讯 POI，保存三项体验和独立推荐；不确定的内容留空。按需补充日期、年龄、来源及 `notes`。头像使用仓库内可公开照片的相对路径，所有公开点共用，不接受站外地址。

维护完成后，你最多操作三步；检查、提交、推送和等待上线由 WorkBuddy 连续执行，无需你逐条运行命令。

1. **导出**：在原浏览器点击「下载待发布 JSON」，保留 `public-places.draft.json`；未保存的预览先保存。
2. **交接**：把文件及下面的指令一起交给已打开本仓库的 WorkBuddy。它先核对差异、完成本地检查并准备提交，展示准确发布结果。
3. **确认发布**：核对 WorkBuddy 展示的变更后回复「按这个结果发布」。WorkBuddy 推送、等待 Pages 并核验正式地址，最后回报提交号、构建链接和上线结果。

可直接复制的交接指令：

```text
请接管此仓库的公开内容发布，按 docs/public-places.md 的“三步发布”执行。
附件 public-places.draft.json 是本次导出的完整公开数据快照。
先核对附件与最新 origin/main 的差异，保留无关改动和新增公共内容；
完成本地导入、检查和提交后，展示地点/评分/推荐变化、完整 diff、提交号、
工作区状态及与 origin/main 的差异，注明尚未推送，供我一次确认。
我确认后，请连续完成推送 main、等待对应 Pages 构建和生产核验，直到回报结果。
遇到内容冲突、权限或检查失败时一次说明具体阻塞；不要把保存、提交或推送当作上线。
```

### WorkBuddy 执行约定

**准备到可确认**：读取附件前先确认文件路径，运行 `git status --short --branch` 和 `git fetch origin`，以最新 `origin/main` 为基线。保留原附件作备份，在干净分支或独立 worktree 中仅合入本次内容。以 `provider + poiId` 比较新增、修改、撤下、头像及三个维度和推荐变化；校验 JSON、唯一 POI、坐标、类别、等级与理由、头像路径符合下方格式。草稿是完整快照且不携带基线，不能直接覆盖最新文件；附件缺少现有地点、出现旧值回退或身份变化时，合并已明确的修改，将不明确的差异集中向维护者确认。没有附件时先索取，不能假定浏览器里的评分已进入仓库。

在最终待发布内容上运行 `npm run check:design`、`npm test`、`git diff --check`，核对手机详情中的本次内容。浏览器环境缺失时修复环境再验证，不能把未运行的测试标为通过。只提交本次发布文件，展示完整提交号、`git show` 的准确差异、工作区状态和与最新 `origin/main` 的比较；此时尚未推送。如果内容已与线上一致，直接核验并回报，无需空提交。

**确认后连续完成**：确认绑定上一步展示的具体提交。再次获取远端，只有 `origin/main` 仍是已核对基线且提交范围全部获准，才用普通快进推送发布提交到 `main`；不用强推。远端前进时重新合并与检查，变更结果有变化则重新展示，不能发布未展示的内容。推送响应不明时先读取远端提交确认是否成功，再决定重试。GitHub 权限、网络和真实内容冲突属于异常阻塞，不能为满足三步跳过检查。

**完成标准**：等待与目标提交 SHA 对应的 GitHub Pages 构建成功（记录任务链接），再读取正式地址 `https://meetwk.site/playmap/` 的页面和 `public-places.json`，分别与目标提交的页面和公开数据核对；用避免旧缓存的请求重试暂时不一致的响应。手机详情中的本次评分/推荐应正确，`https://meetwk.site/playmap/maintainer.html` 必须返回 404。三者都通过才回报“已上线”；等待超时或不一致则回报“已推送，上线未确认”及具体失败项。完成后保留原草稿备份；真人验收及 v1 标签另行决定。

## 格式

下面只是格式示意，不是可发布的真实地点，请替换所有示意值后再加入名单。

```json
{
  "avatar": "assets/11-avatar.jpg",
  "places": [{
    "provider": "tencent",
    "poiId": "确切腾讯POI编号",
    "name": "维护者确认的真实地点名称",
    "address": "真实地址",
    "category": "park",
    "lat": 31.23,
    "lng": 121.47,
    "facilities": { "parking": "yes", "stroller": "limited" },
    "visitedOn": "2026-09-01",
    "experience": "一句真实体验，可省略",
    "fun": { "level": "high", "reason": "孩子喜欢的具体玩法或参与感" },
    "child": { "level": "high", "reason": "儿童参与内容的真实体验", "ages": "年龄参考，可省略" },
    "parent": { "level": "medium", "reason": "带娃便利和麻烦点的真实体验" },
    "notes": "体验与资料的差异或需要补充说明的事，可省略",
    "sources": [{ "title": "场馆资料或实地确认", "url": "https://example.com", "checkedOn": "2026-09-05" }]
  }]
}
```

`child`：`high` 很友好、`medium` 较友好、`low` 有限；`parent`：`high` 很便利、`medium` 较便利、`low` 较费心。等级需同时有理由才展示，否则为“暂无评估”。未评估维度可用 `null` 或省略；`fun` 的 `high` 很好玩、`medium` 比较好玩、`low` 有限。三项高、中、低分别对应 5、3、1 分，等权平均为「11 评分」，保留一位小数；任一项缺少等级或理由不显示总分，不按设施数目算等级。

年龄、日期、体验、补充说明和来源数组都可省略；有引用资料时保留真实来源和核实日期。电话／现场来源可以没有 URL。便利设施只使用 `parking`、`stroller`、`toilet`、`nursing`、`food`，值为 `yes` 或 `limited`；未知省略，不猜测。

类别继续使用公园 `park`、游乐场 `playground`、动物园 `zoo`、水族馆 `aquarium`、博物馆 `museum`、科技馆 `science`、图书馆 `library`、商场儿童区 `mall`、亲水玩沙 `water`、其他 `other`。

## 更新与撤下

同一腾讯 POI 更新原记录，不添加重复记录。撤下时从公共名单移除：没有个人保存关系的图钉消失，用户已经保存的个人副本继续显示普通图钉，公共评估不会复制成个人评价。

历史预制识别仅采用完整已发布默认指纹。旧随机 ID、任何额外字段、评分／记录／照片或个人修改都保留，不能为减少图钉按名称强制删除。

详情页展示「11 评分」及「是否好玩」「儿童友好」「便利程度」三个维度；设施与来源数据仅供维护，不在页面展示。

「是否推荐」在问卷最后独立选择，`recommendation` 为 `strong` 强烈推荐、`general` 推荐、`no` 不推荐；空缺不展示推荐标签，不从星级自动推断。推荐标签显示在评分右侧，不参与三维星级计算。
