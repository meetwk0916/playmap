# 11 到访内容维护

维护者编辑根目录的 `public-places.json`，确认内容后随网站发布。不需要账号或后台；普通用户的个人地点仍只保存在其浏览器。

公开内容只能使用维护者确认的真实到访地点、一句话玩后感和授权公开的照片。现有记录中的评分、三维体验、推荐、设施及来源保留，详情不再显示评分。准确到访日期与打卡年龄显示在详情右上角的草莓章中。统一头像仍使用 `assets/11-avatar.jpg`；打卡照是每个地点单独的一张照片。

## 玩后感与历史数据

现役详情使用可选纯文本 `reflection` 展示「11’s 玩后感」，最多 80 个字符，鼓励一句话说清最鲜明的体验。空值或仅空白不显示整个玩后感区域，不显示默认评价或催填文案。内容按文本显示，不执行 HTML；异常历史值不展示，也不据此删除合法到访记录。

玩后感必须来自维护者提供并确认的真实描述。助手可以精简措辞，但不能从旧评分、照片或坐标推测感受；示意句不能发布为真实经历。不填玩后感也可上图，不再提供评分输入或自动换算。

编辑玩后感、照片或日期时保留已有 `score` 和其他历史字段；新记录不生成 `score`。清空玩后感只移除 `reflection`。旧草稿没有该字段时仍能恢复；未编辑的异常字段、旧日期和扩展字段也保留。历史评分机制见[产品决策档案](product-history.md#2026-10-01到访地记录册与评分显示变化)。

## 地图显示条件

公开 JSON 可以保留待补记录；地图图钉、类别筛选与地点列表统一只显示照片和准确到日的 `visitedOn` 齐全的地点。日期必须是真实日历日期，介于 11 的生日 2024-06-11 与上海时区的当天之间。照片、日期对应同一次到访；评分和玩后感均不参与上图判定。

草莓章使用模型生成的装饰贴纸 `assets/strawberry-stamp.png`，不代表真实到访照片；日期和年龄是页面文字。一地仍只展示一张真实打卡照。

## 相册维护（默认方式）

维护者指定 Google Photos 相册和时间段，由 Codex 或 WorkBuddy 接手已登录网页读取。依次完成：

1. 读取照片日期与页面位置，保留原条目链接；相近坐标按候选区域归组。页面位置可能来自 GPS、手工编辑或估算，坐标只用于找候选。
2. 结合照片画面匹配确切腾讯 POI，沿用已确认的到访地点；住宅、幼儿园及私人日常地点排除，归属不明的集中核对。按 `provider + poiId` 去重。
3. 每个地点从原始照片中选最多一张代表照：优先能表现 11 的到访活动及场所，画面清晰、主体完整；排除模糊、重复和无关照片。只有视频时留空，当前不截帧。画面无法确认场所时展示对应关系，等待维护者核对。
4. 下载选中原图到仓库外的私人核对目录，复用本地维护页的图片处理，生成最长边 960 像素的 JPEG。处理后的文件放在 `assets/visits/`，地点 `photo` 使用相对路径。原图、相册链接、坐标和筛选记录保留在仓库外。
5. 玩后感只采用维护者确认的真实描述，可暂空；旧评分按上方历史数据约定保留。准备页面、地点数据及选中照片，完成检查并展示手机预览和准确差异后，按下方发布确认规则执行。

到访确认与照片对应关系分别核对。公开发布记录保留选中的单张照片，不公开整本相册或私人来源清单。

按需读取和私人清单工具见[私人相册核对清单](album-checklist.md)。

来源索引、候选筛选和已确认批次分别记录；只发布其中一批不代表整个时间段已审完。只有逐条核对完指定时间段的条目，才能报告该时间段完成；未核对范围与来源记录保留在仓库外。

## 手工维护（补充入口）

按 README 启动本地服务，打开 [到访维护页](http://127.0.0.1:4173/maintainer.html)。选择已有地点，填写可选的一句话玩后感（最多 80 个字符），可选择一张打卡照；可填写对应照片的到访日期；玩后感、照片、日期均可暂留空保存草稿；照片和准确日期齐全即可上图，玩后感不必填写。更换照片会覆盖旧照片，也可勾选移除。浏览器将照片缩至最长边 960 像素、转成 JPEG，去掉原图元数据；处理后超过约 330 KB 会拒绝。只选获准公开的真实照片。

预览后保存到独立的本地草稿，再下载完整的 `public-places.draft.json`。照片嵌入该 JSON 的 `photo` 字段；草稿和公开数据不会自动同步，下载也不等于发布。未编辑的 POI 身份和历史字段保留。新增地点从维护页的「本地 POI 搜索」链接（`index.html?maintain=1`，仅本机启用）选择确切腾讯 POI，再使用「11 去过，填写记录」入口；同一 POI 更新原记录。维护页仅在本机地址可用，且不会发布到 GitHub Pages。

草稿键为 `playmap_maintainer_draft_v1`，与个人地图分开。保存失败、草稿不兼容或其他页面并发更新时，不覆盖旧草稿。不同浏览器、端口和 `localhost` / `127.0.0.1` 不共享草稿；换工具时导出 JSON 文件。

## 三步发布（WorkBuddy 接管）

内容准备：确认真实到访与确切腾讯 POI，按需填写一句话玩后感，按需选一张可公开的到访照片；不确定的内容留空。头像使用仓库内可公开照片的相对路径，所有公开点共用，不接受站外地址。

相册维护时，你只需指定来源、核对结果、确认发布：

1. **指定来源**：提供相册和时间段，以及已有的到访确认和真实体验描述。已读取过的来源清单可以直接复用。
2. **核对结果**：助手展示地点对应关系、每处选中的单张原始照片、玩后感及手机详情预览，完成测试和本地提交，并展示准确差异。
3. **确认发布**：回复「按这个结果发布」。助手连续推送、等待 Pages 并核验正式页面、地点数据和每张照片。

手工维护页导出的 JSON 仍可交给助手合入；草稿是完整快照，需和最新公开数据按 POI 比较合并。

可复制的交接指令：

```text
请按 docs/public-places.md 的相册维护方式接管指定相册和时间段。
复用已确认的到访地点，核对确切腾讯 POI，每个地点挑一张最有代表性的原始照片；只有视频时先留空。
玩后感只用我提供并确认的真实描述，可以暂空；保留旧评分，不展示或自动转换。
准备页面、公开地点 JSON 和处理后的单张照片，完成检查和本地提交，展示手机预览、
照片对应关系、完整 diff、提交号及与 origin/main 的差异，注明尚未推送。
我确认结果后，连续完成推送、等待 Pages、核验正式页面、公开数据和照片字节，直到回报结果。
```

### WorkBuddy 执行约定

**准备到可确认**：读取附件前先确认文件路径，运行 `git status --short --branch` 和 `git fetch origin`，以最新 `origin/main` 为基线。保留原附件作备份，在干净分支或独立 worktree 中仅合入本次内容。以 `provider + poiId` 比较新增、修改、撤下、头像、玩后感及照片变化；校验 JSON、唯一 POI、坐标、类别、玩后感长度与照片格式符合下方格式。草稿是完整快照且不携带基线，不能直接覆盖最新文件；附件缺少现有地点、出现旧值回退或身份变化时，合并已明确的修改，将不明确的差异集中向维护者确认。相册方式以指定来源和核对结果准备数据；手工草稿方式须取得导出文件，不能假定浏览器里的玩后感已进入仓库。

在最终待发布内容上运行 `npm run check:design`、`npm test`、`git diff --check`，核对手机详情中的本次内容。浏览器环境缺失时修复环境再验证，不能把未运行的测试标为通过。只提交本次发布文件，展示完整提交号、`git show` 的准确差异、工作区状态和与最新 `origin/main` 的比较；此时尚未推送。如果内容已与线上一致，直接核验并回报，无需空提交。

展示结果前，先发现当前浏览器连接，核对名称、类型和连接标识，再绑定预计用于生产核验的浏览器；工具重置或旧编号失效后重新发现，编号不跨工具会话复用。预检须实际打开页面并读取页面状态；返回 API 说明或取得浏览器对象不算通过，本地 Playwright 通过也不代表该工具可用。手机核验先确认页面实际视口宽高，等待抽屉过渡完成且完整进入视口后再截图或点击；切换视口的中间帧不作为布局结论。

工具连接失败时保留实际调用的错误、耗时和浏览器身份，按工具诊断指引检查；重试一次后仍失败，报告该连接缺失的核验，不推断全部浏览器不可用。分别记录故障触发条件与底层原因：Statsig 未就绪可触发策略加载错误，但单独的未认证 HTTP 403 不能证明正常配置请求为何失败。诊断探测的请求方式与认证条件不一致时，只报告它实际证明的范围。

**确认后连续完成**：确认绑定上一步展示的具体提交。再次获取远端，只有 `origin/main` 仍是已核对基线且提交范围全部获准，才用普通快进推送发布提交到 `main`；不用强推。远端前进时重新合并与检查，变更结果有变化则重新展示，不能发布未展示的内容。推送响应不明时先读取远端提交确认是否成功，再决定重试。GitHub 权限、网络和真实内容冲突属于异常阻塞，不能为满足三步跳过检查。

**完成标准**：等待与目标提交 SHA 对应的 GitHub Pages 构建成功（记录任务链接），再读取正式地址 `https://meetwk.site/playmap/` 的页面和 `public-places.json`，分别与目标提交的页面和公开数据核对，并读取每个本次发布的照片资产，比较字节内容；用避免旧缓存的请求重试暂时不一致的响应。手机详情中的本次玩后感/照片应正确，`https://meetwk.site/playmap/maintainer.html` 必须返回 404。三者都通过才回报“已上线”；等待超时或不一致则回报“已推送，上线未确认”及具体失败项。完成后保留原草稿备份；真人验收及 v1 标签另行决定。

文件核验使用 `npm run --silent verify:production -- <完整提交SHA>`，标准输出为纯 JSON，进度和错误写入标准错误。命令从指定提交读取页面、公开 JSON 和全部 `assets/` 文件，逐字节比较生产响应，并检查维护页 404；每项最多尝试三次、每次请求限时 15 秒，最终有失败则退出码为 1。需要同时等待部署时追加 `--wait-for-pages`：使用当前仓库的 `gh` 登录，约每 10 秒同时查询 Pages 构建与生产文件，最多等待 180 秒；API 短暂失败记录后继续，只有目标提交已构建且全部文件一致才成功。目标构建失败或超时返回非零退出码，不代替 CI 检查。JSON 报告与标准错误日志分别保存到仓库外，复查失败项。文件核验明确标记 `browserInteraction: not-checked`，仍须单独用手机尺寸检查详情玩后感、照片、草莓章和导航。

发布后把提交、CI/Pages 链接、文件核验及手机交互结果集中写入[发布记录](releases.md)。浏览器不可用时写“部署成功、文件核验通过、交互未确认”，整体核验保持未完成。README 和设计文档只指向这份记录。

读取会话日志时先按消息类型和错误关键词定位；应用日志先限定对应时段及最近的相关文件。终端摘要每次最多 10 条、每条最多 700 字符，巨大 JSON 单行先提取所需字段；浏览器发现仅输出本任务连接信息，媒体检查只输出加载状态和文件路径，不打印 data URI 或其他任务的完整标签页信息。原文留在仓库外日志，需要时按位置读取，避免截断使关键证据丢失。

## 格式

每个公开地点保留确切腾讯 POI 身份、名称、坐标和类别。`visitedOn` 是照片对应到访的 `YYYY-MM-DD` 日期，缺少或不完整时不上图。`reflection` 是可选的单行纯文本，去除两端空白后最多 80 个字符，超限明确提示而不静默截断；清空表示移除。旧 `score` 保留，但不展示、编辑或作为上图条件。`photo` 优先使用 `assets/visits/<小写字母数字或连字符>.jpg` 的仓库相对路径，也兼容手工维护页生成的单张 `data:image/jpeg;base64,...`。最长边 960 像素，处理后最多约 330 KB；不填写时省略。旧三维体验、推荐、设施、来源等字段可以继续保留，不在现役详情展示。类别包含 `park`、`playground`、`zoo`、`aquarium`、`museum`、`science`、`library`、`mall`、`water`、`hotel`、`other`。

```json
{
  "avatar": "assets/11-avatar.jpg",
  "places": [{
    "provider": "tencent",
    "poiId": "确切腾讯POI编号",
    "name": "维护者确认的真实地点名称",
    "address": "真实地址",
    "category": "hotel",
    "lat": 31.23,
    "lng": 121.47,
    "reflection": "示例玩后感，须替换为维护者确认的真实体验。",
    "visitedOn": "2026-09-12",
    "photo": "assets/visits/example-visit.jpg"
  }]
}
```

示例不是可发布的真实地点或照片。不要把测试数据当作 11 的经历。

## 更新与撤下

同一腾讯 POI 更新原记录，不添加重复记录。撤下公共记录时，已有个人副本继续保留。历史预制识别仍只采用完整已发布默认指纹；旧记录、个人评分和照片不会因公开详情调整而丢失。
