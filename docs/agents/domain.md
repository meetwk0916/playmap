# Domain Docs

This is a single-context repository.

- Read root `CONTEXT.md` before naming domain concepts in issues, tests or proposals.
- Use its terms instead of inventing synonyms.
- Treat missing terminology as a gap to resolve with domain modeling, not as permission to create parallel language.
- Read relevant files under `docs/adr/` if that directory is introduced later; surface conflicts instead of silently overriding a decision.
