# 11去哪玩

记录 11 到访过的地点：在地图上查看地点、一句话「11’s 玩后感」与一张到访打卡照。

## 运行

```bash
npm run dev
```

打开 <http://127.0.0.1:4173/index.html>。应用使用原生 HTML/CSS/JavaScript 和腾讯地图 GL JS API；地图与维护页共用 `assets/visit-rules.js` 解释到访记录。数据保存在浏览器 `localStorage`，不需要后端。公开记录来自仓库 JSON，旧个人数据保留在原有存储键中。

生产站点为 <https://meetwk.site/playmap/>，由 GitHub Pages 从 `main` 分支根目录发布并强制使用 HTTPS。

## 腾讯地图配置

生产页面使用受域名限制的浏览器 Key 加载腾讯地图 GL JS，并供地点搜索降级通道复用。腾讯位置服务控制台必须允许 `meetwk.site`，同时为地点搜索启用 WebService API 和相应配额。本地调试在线搜索还需允许 `127.0.0.1:4173`，并通过上面的 HTTP 地址打开；`file://` 页面没有可授权来源，不支持在线搜索。启动与浏览器测试会校验 4173 是否服务于当前工作目录；发现其他目录或无响应服务时停止并报告，不自动结束占用进程。

浏览器 Key 会随页面源码公开，必须依靠域名白名单和额度限制控制使用范围。不要把腾讯地图 SecretKey/SK 写入 HTML、JavaScript 或仓库；如需使用 SK，应改由服务端代理持有。

## 验证

```bash
npm run check:design
npm test
```

`npm run check:design` 包含设计令牌门禁，以及 `npm run check:places`：公开地点 `address` 必须能被地点列表解析出「…市」。`npm test` 使用 Playwright，并自动启动 4173 端口的静态服务器；首次运行前需安装项目依赖及 Playwright Chromium 运行环境。

首轮本地诊断可用 `npm test -- --max-failures=1`，让运行器在首次失败后停止，避免重复启动故障。根据失败日志判断原因：`browserType.launch` 中的 Chromium 缺失、系统动态库缺失或 macOS `MachPortRendezvousServer ... Permission denied` 表示浏览器启动环境受限；浏览器已启动后的页面断言失败仍需按产品问题排查，不能把首次失败一概归为环境问题。

缺少浏览器时运行 `npx playwright install chromium`；缺少系统依赖时按 Playwright 的系统依赖提示修复；启动权限受限时说明具体限制，使用获准的执行方式或请求必要权限。未启动或未执行的测试不得标为通过。环境修复后，在最终内容上完整运行 `npm run check:design`、`npm test` 和 `git diff --check`，报告实际结果及未通过项；首次失败停止的诊断轮不能替代完整检查，也不代表部署或真人验收。

[检查工作流](.github/workflows/checks.yml) 在推送到 `main` 或向 `main` 提交 PR 时运行上述两项检查，并自动安装 Chromium 及系统依赖。

相册辅助工具另运行 `npm run test:album`，现有 CI 已配置该项。逐项执行检查，记录命令、退出码、简短结论和完整日志路径；命令依赖前项成功时使用 `&&`。完整输出保存在仓库外，失败与未运行项分别报告，终端只展示必要摘要。

发布核验工具与本地服务身份检查的回归使用 `npm run test:release`，已接入 CI，使用本地测试服务器。生产文件核验使用 `npm run --silent verify:production -- <完整提交SHA>`，可追加 `--wait-for-pages` 同时等待目标部署；交互验证另行执行，详见[发布流程](docs/public-places.md#三步发布workbuddy-接管)。

## 产品范围

地图仅显示维护者确认的 11 到访地点，且每条记录须同时具备确切腾讯 POI、一张打卡照及准确到日的到访日期。缺照片或日期的记录保留在维护数据中待补，不上图；评分和玩后感均不是显示条件。点击图钉或地点列表，详情展示地点名、类别、可选的一句话「11’s 玩后感」、一张照片，以及右上角草莓章中的到访日期和打卡年龄；导航位于照片下方。生日按维护者提供的 2024-06-11 计算已满的年月。玩后感最多 80 个字符，只使用维护者确认的真实体验；为空时不显示该区域。历史评分和体验字段保留，但不展示或自动转成玩后感。

保留原有类别筛选、按需定位和地点列表；类别筛选只筛选完整到访记录，不再补充在线候选。底图保留道路和地名、隐藏 POI 标注。普通地图页面不再提供搜索新地点、个人添加、个人地图及复制目的地入口。新增公开地点仍须绑定确切腾讯在线 POI，本机维护时从 [维护页](maintainer.html) 进入本地 POI 搜索。

旧个人地点、历史评分、记录和照片继续保存在原浏览器存储中，页面不再读取其中的地点内容、自动迁移或重写它们；只有用户在「数据与隐私」中明确两次确认清空时才改变这份存储。公共记录不能由访客修改或删除，维护草稿仍与个人存储分开。

默认由维护者指定 Google Photos 相册和时间段，Codex 或 WorkBuddy 读取日期与位置、核对腾讯 POI，并为每个已确认到访地点挑选最多一张原始照片。只有视频的地点暂不配照片。维护者核对具体选片和发布结果后，照片与地点数据一起部署。详见 [11 到访内容维护](docs/public-places.md)。[本地维护页](maintainer.html)保留为手工补充入口。

地图不可用时，页面保留完整公开地点的列表浏览与详情。旧个人数据原文保留，读取存储失败也不覆盖。定位仅在用户主动点击后申请权限，不会保存为地点。

## 发布边界

各次发布的提交、部署与核验结果先记录在原 PR，随后随正常 PR 汇总到[发布记录](docs/releases.md)；产品范围说明不作为部署凭据。

公开内容交给 WorkBuddy 发布只需「指定相册与时间段 → 核对地点和选片 → 确认发布」，检查和上线核验由它执行；可复制指令及完成标准见 [三步发布](docs/public-places.md#三步发布workbuddy-接管)。

公开记录随 `main` 分支通过 GitHub Pages 发布；是否上线以 Pages 构建和生产页面、公开数据核对结果为准。代码测试、提交、推送、部署和真实使用反馈分别记录。旧 Wayfinder 的五家庭导航验收门槛不作为这次记录册调整的验收标准；新方向尚未制定真人验收标准或发布 v1 标签。
